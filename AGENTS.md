# Bruin AI Quest development rules

1. Keep the UCLA resource registry factual, source-linked, and dated.
2. Never imply this is an official UCLA service or endorsement.
3. Treat availability, eligibility, pricing, and data-protection claims as time-sensitive.
4. Keep decision backends separate from rendering and pathfinding.
5. Jev makes fuzzy routing judgments; deterministic code owns movement, UI, and exact logic.
6. Keep an offline rules backend so demos/tests do not depend on external APIs.
7. Do not commit credentials, personal data, restricted or unpublished research data, internal institutional information, or collaborator-only material.
8. Biomedical example missions must use synthetic or clearly public data.
9. Preserve backend interchangeability for future Jev / Kev-4B / rules comparisons.
10. Log enough state to reproduce routing experiments without logging secrets.
